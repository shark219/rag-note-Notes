## 二、整体架构流程

```
用户请求 → ChatService → AgentService (入口) → Supervisor 分诊
    → AgentLoop (核心循环) → ResponseComposer (回答生成)
    → QualityReviewer (质量审查) → SSE 流式返回
```

### 详细流程

#### 阶段 1：入口 — `AgentService.streamAgentResponse()`

**文件**: `agent/AgentService.java` (约726行)

1. 创建 SSE 连接，异步执行（CompletableFuture）
2. 保存用户消息到数据库
3. 加载会话历史 → `ContextManager.buildMessages()` 滑动窗口压缩
4. 根据用户开关过滤工具列表（知识库、笔记功能的开关）
5. 注入附件上下文（如果有上传文件）
6. **Supervisor 分诊** → 判断任务是否要拆分子任务

#### 阶段 2：任务分诊 — `SupervisorService.plan()`

**文件**: `agent/SupervisorService.java:46-222`

- 用 LLM 分析用户查询
- 返回 `SubTask` 列表：
  - **空列表** → 简单任务，走**单 Agent**
  - **多子任务** → 走**多 Agent 流水线**（顺序或并行）
- 拆分规则来自 resource 下的 prompt 模板

#### 阶段 3A：单 Agent 路径

```
AgentService → AgentLoop.run() → AgentLoopResult → ResponseComposer → QualityReviewer
```

**AgentLoop 核心循环 — `agent/AgentLoop.java` (约623行)**

```
Goal → Action → Observation → State Update → Goal Check → Done / Continue
```

最多 10 轮迭代，每轮：

1. **连续 2 轮无进展** → 注入环境状态视图让 LLM 重新审视
2. **LLM 生成** → `createPreciseModel()` (temperature=0.1)
3. **如果 LLM 调用工具**:
   - 防重复拦截（同工具同参数已失败 / 与上一轮完全相同的调用）
   - 执行真实工具（`executeTool` → `AgentTools` 的各种方法）
   - `ToolResultEvaluator` 评估结果质量（GOOD / POOR / ERROR）
   - 构建 **Observation** 消息注入给 LLM
   - GOOD 结果时 → **GoalEvaluator** 判断目标是否达成
     - 达成 → 直接结束循环
     - 未达成 → 注入进度提示，继续下一轮
4. **如果 LLM 直接返回文本**（不调工具）:
   - 第 1 轮无工具调用且是反问 → 返回 `NEED_CLARIFICATION`
   - GoalEvaluator 检查 → 拦截（要求继续调工具）或放行

##### 防重复和反思机制

- **同工具同参数已失败过** → 拦截并注入状态+建议
- **与上一轮完全相同的调用** → 拦截并提示换策略
- **连续无进展 ≥ 2 轮** → 注入环境状态视图

#### 阶段 3B：多 Agent 流水线

##### 顺序执行

```
子任务1 → AgentLoop → 结果 → 子任务2 (带上一步上下文) → AgentLoop → 结果 → ... → WriterService 合成
```

每个子任务有独立的目标和成功标准，上一步结果注入下一步的上下文。

##### 并行执行

```
子任务1 → AgentLoop (并行) ─┐
子任务2 → AgentLoop (并行) ─┤ → CompletableFuture.allOf → WriterService 合成
子任务3 → AgentLoop (并行) ─┘
```

#### 阶段 4：回答生成 — `ResponseComposer.compose()`

**文件**: `agent/ResponseComposer.java:37-206`

从 `AgentState` 提取 **EvidencePack**（笔记证据、知识库摘要、产物等），调用 LLM（temperature=0.5）生成自然回答。

#### 阶段 5：质量审查 — `QualityReviewer.reviewAnswer()`

**文件**: `rag/QualityReviewer.java:85`

检查回答质量，不通过则重新生成。

#### 阶段 6：SSE 流式返回

- `thinking` 事件（轮次、工具调用等进度）
- `response` 事件（50 字/块分块推送）
- `done` 事件（含 session_id、trace_id、token 用量、产物数据）

## 四、关键设计亮点

1. **目标驱动**：不再要求 LLM 调特定工具，而是给目标让它自主决策
2. **GoalEvaluator LLM 自检**：用 LLM 判断目标是否达成（`checkGoalWithLLM`），而非硬编码关键词
3. **有序的防重复机制**：同参数失败拦截 + 机械重复拦截 + 环境状态注入，避免 LLM 死循环
4. **证据级别体系**：LIST → SEARCH → CONTENT → ARTIFACT，从浅到深，`EvidencePack` 自动去重保留最高级别
5. **会话上下文管理**：`ConversationContextManager` 解决"这篇笔记"、"它"等代词指代问题
6. **质量审查兜底**：每次回答生成后经过 `QualityReviewer` 检查，不通过则重试
7. **Supervisor 分诊**：简单任务走单 Agent（减少延迟），复杂任务走流水线

## 七、完整的 Agent 执行流程

```
用户发送消息
     │
     ▼
AgentService.streamAgentResponse()
     │
     ├── 1. 保存用户消息到 MySQL
     ├── 2. 加载会话历史 → ContextManager 滑动窗口压缩
     ├── 3. 根据用户开关过滤可用工具
     ├── 4. 注入附件上下文（如有上传文件）
     │
     ▼
SupervisorService.plan(query)  ← LLM 分诊
     │
     ├── 返回空列表 ──────────────────→ 走单 Agent
     │                                    │
     │                                    ▼
     │                              AgentLoop.run()
     │                              (最多 10 轮迭代)
     │                                    │
     │                              ┌─────┴─────┐
     │                              │           │
     │                              ▼           ▼
     │                         调用工具      返回文本
     │                              │           │
     │                              ▼           ├─ 反问 → NEED_CLARIFICATION
     │                         ToolResult       ├─ GoalEvaluator 拦截 → 继续
     │                              │           └─ GoalEvaluator 放行 → 完成
     │                         ToolResultEvaluator
     │                         (GOOD/POOR/ERROR)
     │                              │
     │                         GoalEvaluator
     │                         (目标达成了吗?)
     │                              │
     │                         ┌────┴────┐
     │                         │         │
     │                     达成 ✔    未达成 ✘
     │                         │         │
     │                     结束循环   注入Observation
     │                         │     继续下一轮
     │                         ▼
     │
     ├── 返回多子任务 ──────────────→ 走多 Agent 流水线
     │                                    │
     │                              ┌─────┴─────┐
     │                              │           │
     │                              ▼           ▼
     │                         顺序执行      并行执行
     │                              │           │
     │                              ▼           ▼
     │                         WriterService.synthesize()
     │
     ▼
ResponseComposer.compose(EvidencePack)
     │
     ▼
QualityReviewer.reviewAnswer()
     │
     ├── 通过 → SSE 流式返回
     └── 不通过 → 重新生成
```
